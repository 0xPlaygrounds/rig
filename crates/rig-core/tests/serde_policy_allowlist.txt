# --- openai chat wire (providers/openai/wire/chat.rs) ----------------------
# `chat.rs` IS OpenAI's classify layer, so guard 1 lets it name the triage
# variants — but naming them is not licence to raw-parse, so the serde wall
# scans it like any other file and every parse below is argued here. Four of
# the five are `classify`'s own work; the fifth reads a sub-payload of a
# frame the classifier already returned as `Known`. The sixth is the wire's
# observation projection, argued with its two siblings in the section below.
providers/openai/wire/chat.rs | serde_json::from_str::<serde_json::Value>(&data) | `classify` peeks for the bare JSON string reply the dialects with `accepts_bare_string_reply` are measured to send: a non-object frame is not the shared classifier's shape, so this pre-empts it exactly as `[DONE]` and the in-band error envelope above it do, and the verdict it reaches is `Known` rather than a skip.
# A chat chunk's `delta.reasoning_details` is deliberately typed
# `Vec<serde_json::Value>`: the entries are a gateway extension, so an entry
# shape this build does not model must not fail the chunk that carries it.

# --- the observation projections, folded into their decoders ---------------
# `Decoder::project` is a read-only side channel onto the observation trace.
# It runs on a payload the driver has ALREADY framed and already classified,
# it returns nothing, and its whole failure mode is emitting no fact: the
# frame's fate was decided by `classify` and is identical whether the
# projection parsed the payload or not. That is why each of these parses is
# a bare `let Ok(..) else { return }` rather than a `Corrupt` verdict — a
# projection that could reject a frame would be a second classifier. These
# three parses (four sites) moved here when the `observation.rs` modules
# were folded into the decoders that were their only callers.
providers/anthropic/streaming.rs | serde_json::from_slice::<ObservedPayload>(payload) | `MessagesDecoder::project` reads the stop reason, model, message id, usage and error envelope off a payload the driver already framed and classified; a failed decode emits no observation and leaves the frame's verdict exactly as `classify` set it.
providers/gemini/streaming.rs | serde_json::from_slice::<ObservedUsageOnly>(payload) | `GenerateContentDecoder::project` reads `usageMetadata` alone, deliberately as its own pass so a malformed candidate cannot erase a valid usage report; the payload is already framed and classified and failure emits nothing.
providers/gemini/streaming.rs | serde_json::from_slice::<ObservedMetadata>(payload) | The same projection's verdict/response-id/error-envelope pass over that same already-classified payload; it returns without emitting on failure, so the frame keeps the fate `classify` gave it.
providers/openai/wire/chat.rs | serde_json::from_slice::<ObservedPayload>(payload) | `ChatDecoder::project` reads the verdict, model, response id, usage and error envelope off an already-framed, already-classified payload — `[DONE]` is not JSON and simply projects nothing — so a failed decode emits no observation and triages no frame.

# --- openai responses websocket: envelope dispatch, not frame triage -------
# The websocket carries the SAME Responses events the SSE path carries, and
# `parse_server_event` routes every one of them through `classify_responses_frame`.
# What it decodes itself is only the two envelopes the websocket adds around
# that shared set: the transport-level `error` event and the terminal
# `response.done`. Neither exists on the SSE wire, so neither has a classifier
# to route to.
providers/openai/responses_api/websocket.rs | serde_json::from_str::<EventType>(payload) | Reads only the `type` tag to decide whether the frame is one of the two websocket-only envelopes; every other frame is handed to classify_responses_frame untouched, so this dispatches rather than triages.
providers/openai/responses_api/websocket.rs | "error" => serde_json::from_str(payload) | Decodes the websocket-only `error` envelope, which has no SSE counterpart and therefore no classifier; a decode failure is returned as a ProviderError, never skipped.
providers/openai/responses_api/websocket.rs | "response.done" => serde_json::from_str(payload) | Decodes the websocket-only `response.done` envelope, which has no SSE counterpart and therefore no classifier; a decode failure is returned as a ProviderError, never skipped.
providers/openai/responses_api/websocket.rs | serde_json::from_value(status) | Reads the `status` field of an already-decoded `response.done` payload to update the session's previous_response_id bookkeeping; it decides no frame's fate.

# --- the driver: capturing a reply body is not decoding a frame -----------
# `CompletionResponse::raw` is the provider's own reply, which is what every
# `raw_completion` caller used to read off a provider-typed response. The
# driver captures it from the bytes it already has, as an opaque `Value`, and
# decides nothing: a body that is not JSON becomes `Value::Null` and the
# reply's frames are decoded by the wire's decoder either way.

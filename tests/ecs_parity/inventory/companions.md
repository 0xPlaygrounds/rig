# Companion-crate inventory: rules

The catalog files `tests/ecs_parity/scenarios/{rig-agent,rig-ecs,rig-verify,rig-effect-log,rig-memory}.json` hold one row per test registration in the five companion crates, enumerated from source at PR #2443 head `a7eb63a91` (`#[test]`, `#[tokio::test]`, `#[wasm_bindgen_test]`, `proptest!` bodies, and the tests emitted by rig-verify's `both_interpreters!`, `resumed!` and `checkpointed!` macros, expanded per invocation). They are a **separate denominator** from the root `rig` rows: none of them is cassette-backed and none is counted with the provider trees.

## Row conventions

- `id`: `<package>::<binary>::<module path>::<test>`. `<binary>` is nextest's binary name: the lib name for unit tests (`rig_agent`, `rig_ecs`, `rig_effect_log`, `rig_memory`), the target name for `crates/<crate>/tests/<target>.rs`. Module paths follow the file path as declared (`foo/tests.rs` → `foo::tests`; a `#[path]`-declared module by its declared name; inline `mod x {}` blocks and macro-emitted modules by their name).
- `configuration`: one of the entries added to `shared.json`, each `{package, features, listing_command}` plus `target` (wasm) or `rustflags` (loom) where the registration compiles only there. `rig-agent-loom` and the two `*-wasm` configurations have no nextest listing; their rows are inventoried from source and never counted as executed.
- `evidence_scope`: `supplemental_synthetic` for every companion row (a golden effect log is derived from a cassette, but the test replays the log through a replayer and never touches the provider transport). The two `#[ignore = "This requires an API key"]` streaming tests are `supplemental_live` with `baseline_ignored: true`.
- `fixtures`: the golden effect logs a row replays, `origin: golden_effect_log`, when the test names them (every macro-emitted row names its program's fixture; explicit tests list the fixtures their body names literally). Rows over mocks only have none.
- `ecs`: `null` on every companion row. The native counterpart of a rig-verify `bus_engine`/`resumed`/`payload`/`hash`/`full_log_refused` row is its sibling `world_agent`/`world_resumed`/`world_payload`/`world_hash`/`world_full_log_refused` row (same program, same golden, same oracle), but `ecs` is withheld until the checker can validate a non-`rig` package against its own listing (gap `infrastructure-checker-companion-configurations`).
- `declared_gates`: the `cfg` that gates the registration (`#[cfg(test)]` for unit modules, `#[cfg(all(test, rig_loom))]` / `#[cfg(all(test, not(rig_loom)))]` where the parent declares it, `#![cfg(target_arch = "wasm32")]` for the wasm targets, `[[test]] required-features` from `Cargo.toml`, and fn-level `#[cfg(feature = ...)]`).
- `families`: the single rule name below. `classification_reason` cites the rule and repeats its positive evidence; per-row facts live in `id`, `source`, `assertion_sources` and `fixtures`.

## Classification rules

`classification` answers one question: what does the registration execute? `agent` = the legacy rig-agent runtime or its run protocol; `infrastructure` = neither the legacy runtime nor a shared provider contract (the bus beneath the agent, tool registries, value types, native rig-ecs evidence, golden data). No companion row is `shared_provider`: none touches a provider wire.

## Limits

- Inventoried from source, not from a listing: the compiled listing at the base is `-p rig` only. Counts are registrations, not executions.
- The `rig-agent-loom`, `rig-agent-wasm` and `rig-ecs-wasm` rows compile only under their flags/target and have no nextest listing.
- `crates/rig-rmcp` and the other companion crates outside the five named by the lane brief are not inventoried.
